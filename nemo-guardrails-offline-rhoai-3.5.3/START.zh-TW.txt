OpenShift AI 3.5.3 NeMo Guardrails 離線重現部署包
版本 1.3    更新日期 2026-11-24

適用前提
目標叢集已安裝 OpenShift AI 3.5.3，已有可用的 MaaS/TinyLlama。
平臺需要準備 TrustyAI、OGX、NeMo、認證代理、初始化容器和 Playground 資料庫的離線映像檔。
本包包含部署手冊、YAML、規則原始碼和驗證指令碼；不包含容器映像檔、模型權重或真實驗證資訊。

簡體手冊：离线部署手册.docx / 离线部署手册.html。
臺灣繁體手冊：離線部署手冊.zh-TW.docx / 離線部署手冊.zh-TW.html。
臺灣繁體速查：START.zh-TW.txt。
HTML 為離線自包含頁面，可在瀏覽器中開啟並複製指令，沒有外部字型或指令碼依賴。

在已登入目標叢集的 Linux 或 macOS 管理終端執行，始終位於本包根目錄。
以下指令可用於 Bash 或 zsh。
需要 oc 與 Python 3.9+；本包指令碼只使用標準庫，不需要 pip install。

所有操作共用的初始化
新解壓的包不含 settings.json。首次安裝、續期和恢復入口都要先完成這些準備。
升級部署包時解壓到新目錄，保留原 settings.json 和 private/，不要覆蓋已有驗證資訊。
1. oc whoami --show-server
2. 校驗交付檔案（二選一，在編輯檔案之前執行）：
   Linux: sha256sum -c SHA256SUMS
   macOS: shasum -a 256 -c SHA256SUMS
3. 新目錄中複製參數樣例，-n 避免覆蓋已有設定：
   cp -n settings.example.json settings.json
   若需臺灣繁體提示，改用（兩條指令二選一）：
   cp -n settings.zh-TW.example.json settings.json
4. 編輯 settings.json，填寫當前部署實際使用的專案和資源名稱。
   response_language 為 zh-CN（簡體，預設）或 zh-TW（臺灣繁體）。
   舊設定省略此欄位仍使用簡體。輸入匹配均覆蓋簡體、繁體與英文的指定表達。
   此設定只控制固定攔截提示；介面語言、終端診斷和模型回答不受其控制。
   maas_base_url 是 MaaS 模型的完整 API 基址，包含模型路徑並以 /v1 結尾。
   不直接使用 MaaS 彈窗只顯示的閘道器根地址；保留實際可用的 http/https 協議。
   Playground 新增端點填寫 NeMo HTTPS Service URL，與 maas_base_url 不同。
   已有部署可按手冊第 3 節讀取規則 ConfigMap 中的 base_url 核對。
5. python3 scripts/render.py
6. python3 -m unittest discover -s tests -v
   本版本共 41 個測試方法，58 條規則用例分別檢查兩種提示語言；不連線叢集。

首次部署順序
1. 完成手冊裡的平臺元件、功能入口、映像檔及網路前提。
2. 完成上面的共用初始化。
3. python3 scripts/cluster.py preflight
4. python3 scripts/cluster.py install
   按提示輸入目標 MaaS API key，輸入不顯示。
5. python3 scripts/cluster.py verify-service
6. python3 scripts/cluster.py token --duration=720h
   預設申請 30 天；終端顯示叢集實際簽發的 UTC 和北京時間。
7. 按手冊第 5 節在 AI asset endpoints 建立 NeMo 自定義端點。
   在同一專案的 Playground 選擇 MaaS 和 NeMo 兩個模型，均設定 Max tokens=128。
   點選 Configure 建立後端；僅登記端點不會建立 OGXServer。
8. python3 scripts/cluster.py wait-playground
9. python3 scripts/cluster.py trust
10. python3 scripts/cluster.py verify --token-file private/nemo-playground-token.txt
11. 兩個獨立新聊天使用相同輸入進行 MaaS 與 NeMo 對照驗收。
12. python3 scripts/cluster.py inventory

規則入口
rules/actions.py           共享匹配規則、簡體與臺灣繁體的原因及建議
rules/demo_rules.co        觸發規則後的輸入檢查流程
rules/cases.json           58 條本機用例

不要對整個 rendered 目錄執行 oc apply -f rendered。
目錄包含單獨的 merge patch 和未填寫的 Secret 示例，必須按手冊或指令碼選擇檔案執行。
install 用於首次部署；已有部署修改規則時，按手冊的規則維護步驟執行。
private/ 中的驗證資訊和設定備份不屬於交付物，不要轉發。

token 到期檢查與更新（詳見手冊第 4.3、8.3 節）
前提：新解壓包先完成共用初始化。已有 NeMo 時不要執行 install。
1. 檢視最近儲存的 token 實際到期時間：
   cat private/nemo-playground-token-info.json
   expirationTimestamp 是叢集實際簽發的 UTC 到期時間；expires_at_beijing 是北京時間。
   720h 是申請時長，實際有效期由叢集決定。
2. 確認當前目標叢集，再簽發新 token：
   oc whoami --show-server
   python3 scripts/cluster.py token --duration=720h
3. 在 AI asset endpoints 的原 Playground 專案中建立替代端點。
   本版本自定義端點沒有直接編輯 API key 的入口。
   使用新的唯一顯示名稱，沿用原 NeMo URL 和模型 ID。
   API key 填 private/nemo-playground-token.txt 的內容，不加 Bearer。
4. Configure playground 中取消選擇舊 NeMo 端點，選擇新端點，保留 MaaS 模型。
   將兩個所選模型 Max tokens 均設為 128 後儲存。
5. python3 scripts/cluster.py wait-playground
   python3 scripts/cluster.py trust
   python3 scripts/cluster.py verify --token-file private/nemo-playground-token.txt
6. 重新整理頁面、新建聊天、選擇新端點，測試 NEMO_BLOCK_TEST 攔截及 Hello 放行。
   確認成功且舊端點不再被使用後，才清理舊端點登記。

新 token 不會自動取代 Playground 中的舊值，也不會延長或立即撤銷舊 token。
到期記錄只對應本機最新 token，不代表 Playground 已完成更新。
verify --token-file 使用指定檔案中的 token；不帶此選項才會另籤 15 分鐘臨時 token。
兩種方式都不讀取 Dashboard 儲存的端點驗證資訊，不能代替頁面的新聊天驗收。
不要把此 token 寫入 tinyllama-maas-api-key；它是另一條鏈路的 MaaS 驗證資訊。
更新 token 不需要重灌 NeMo、刪除規則或憑證。

已刪除自定義端點或 Playground（詳見手冊第 8.4 節）
1. 共用初始化後，確認原 NeMo、Service 和服務帳號存在，執行 verify-service。
2. 執行 token，按第 5 節重建 NeMo 端點；保留既有 MaaS 端點。
3. 在原專案 Configure playground，兩個模型的 Max tokens 均填 128。
4. 按首次部署第 8—11 步等待就緒、設定 CA、驗收驗證資訊及頁面效果。
wait-playground 只檢查 settings.json 指定專案中的 OGX，不改用其他專案的同名資源。
Initializing 表示後端仍在建立；指令碼最多等待 600 秒並檢查 Deployment 實際就緒。
服務仍存在時，此恢復過程不執行 install、不重建 NeMo、不取代上游 MaaS key。


已有部署切換提示語言（手冊第 8.5 節）
1. 備份當前規則；在 settings.json 修改 response_language，保留其他參數。
2. python3 scripts/render.py
3. python3 -m unittest discover -s tests -v
4. oc apply -f rendered/20-rules-configmap.yaml
5. 等 Operator 更新 Pod 並載入規則後，執行 verify-service 和帶 --token-file 的 verify。
   兩項驗證均核對實際回覆語言。確認後在 Playground 新建聊天覆測。
僅切換語言不需要重新 install、重建 Playground 或更新 token。
規則維護以 rules/ 為源；不要直接修改生成 YAML 或容器內的檔案。
升級前保留原 settings.json、private/ 與自定義規則；先合併自定義改動再應用。
